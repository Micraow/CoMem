06

做与不做

上一版被指出的问题，逐条对照。

这样做
正文 15–16px，最小 14px表格与标识符单独定 14px，只有 chip 里的短标签允许 12–13px。
按钮 40px 高，带 state layer悬停 8%、按下 12% 的半透明覆盖层，涟漪用 CSS 动画实现。
8px 网格与 16px 卡片内边距卡片内边距最小 16px，行高 1.5，长段落限宽。
语义色 + 图标 + 文案三重表达pending 不靠颜色区分，同时给徽标文字与图标。
深浅两套完整方案默认深色，切换后所有角色重新映射，对比度分别校验。
不要这样做
10–11px 的辅助文字信息密度不是靠压字号换来的；放不下就拆面板、折叠次要信息。
四种按钮长得一样层级差异要靠填充、描边、容器色区分，不能只靠字号和灰色。
纯扁平、无阴影没有 elevation 就失去了 MD3 的层级语义，卡片与背景糊成一片。
组件里写死 hex一律引用角色 token，否则深浅切换必然出现某个角落没跟上。
把内部术语露在界面上界面上一律叫「元数据文件」，状态叫「基线 / 待刷新」，不出现 page_id、digest 这类字段名。
