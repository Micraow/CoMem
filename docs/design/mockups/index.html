CoMem Console · 静态视觉稿 · v0.1

把 agent 的记忆，做成一座可检索的档案库。

CoMem 是面向 AI agent 的上下文记忆数据库。所有资源、记忆、技能都挂在 comem:// 虚拟文件系统下，按 L0 一句话摘要、L1 目录概览、L2 原文三层渐进披露。 这套控制台是给人用的：查一条记忆从哪来、被谁改过、摘要是否落后、哪些主体能看见它。

01 设计方向 Archive Instrument

整体是「档案库里的仪器面板」：暖石墨底色（不是常见的蓝黑）、只有一种琥珀色作为信号色、 全部边界用 1px 发丝线而不是阴影分层、数据列一律等宽字体加表格数字。 信息密度按开发者工具来定，行高 25–28px，一屏尽量多放条目。

贯穿全套页面的视觉母题是「地层」：三条长度递减的横线，分别代表 L0 / L1 / L2。 它在左上角是 logo，在详情页是层级切换器，在检索结果里是命中层级，在复核页是记忆的深度。 同一个符号反复出现，用户不需要再学第二套图例。

做
  • 发丝边框、2–5px 圆角、无外阴影（浮层除外）
  • 单一琥珀信号色 + 语义色只用于状态
  • URI、字段名、状态值、数字全部等宽
  • 用留白和分割线分区，不靠卡片堆叠
不做
  • 紫蓝渐变、发光球体、玻璃拟态
  • 大于 8px 的圆角、彩色图标底板
  • 营销式空状态插画与装饰性动效
  • 把内部字段名（page_id、digest）暴露到界面

02 页面索引 6 个工作面

01 / FILESYSTEM
文件树
左树右详情。详情可在 L0 / L1 / L2 之间切换，并交代摘要由谁生成、何时生成、是否待刷新。
↗
02 / RETRIEVAL
检索调试台
对比 find 与 search 两种模式的召回差异，展示意图拆解出的多条查询、每条命中的分数与层级，以及 ACL 到底过滤掉多少条。
↗
03 / REVIEW
记忆复核
抽取出的「经验」与「规则」在生效前需要人工过一道。左右并排看 before / after，规则额外展示适用条件与例外。
↗
04 / PERMISSION
权限管理
节点树标出 restricted 边界，右侧列出主体、级别、来源，并用一条推导链解释「有效权限」是怎么算出来的。
↗
05 / ADMIN
用户与组
用户、组、组成员、组空间默认权限。管理者需要在一屏内判断谁能进哪个空间。
↗
06 / SESSIONS
会话与后台任务
会话提交后进入归档与抽取管线。任务状态、重试次数、僵尸锁回收记录都必须可见，进程崩了才知道从哪续。
↗

03 色板 单信号色 · 暖中性

05 间距与结构 4px 基准

间距刻度
4 · 8 · 12 · 16 · 22 · 26 · 40 · 56。组件内 8/12，区块间 22/26，页面级 40/56。
行高
表格行 33px、树行 25px、列表行 52–64px。密度靠行高控制，不靠缩字号。
圆角
控件 3px，面板 5px，标记 2px。圆角只用来软化边缘，不承担层级。
边框
统一 1px，颜色 rgba(232,233,226,.09)；强调边界 .17；强分割 .28。
外壳
顶栏 46px + 侧栏 214px + 主区自适应。主区独立滚动，侧栏固定。
栅格
左右分栏 300 / 320px，详情页右侧元数据栏 296px，最小可读宽度 980px。
动效
悬停 100–140ms、进入 300ms ease-out、仅位移与透明度，尊重 prefers-reduced-motion。

07 阅读约定 演示说明

数据
全部为手工构造的演示数据，URI 与字段名遵循 comem:// 命名规范，可直接对照接口文档阅读。
交互
目录可展开、条目可选中、层级可切换、任务可重试。所有改变只发生在页面内，不请求后端。
主题
右上角切换，选择记在 localStorage，跨页面保持。
文案
界面语言为中文；URI、字段名、状态值、主体标识保留英文原文，避免对接时二次翻译。
