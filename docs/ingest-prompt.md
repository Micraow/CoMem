# 把旧对话导入 CoMem

打开 CoMem 控制台的 **会话与任务 → 导入历史会话**，复制提示词，粘贴到一个能读取你的导出文件、也已接入你的 CoMem 的 Agent。告诉 Agent 要读哪个文件或目录，也可以直接把要导入的文本交给它。先检查预览里的来源、会话数及跳过项，再确认导入。也可直接从仓库[复制提示词原文](../web/assets/prompts/import-history.md)，与网页使用的是同一份。

Agent 可以按内容识别 Codex 会话导出、其他宿主的结构化日志或普通文本里的角色标记，不需要预先把所有文件转成一种格式。解析能力取决于 Agent；没有明确说话人的文本可在确认后整段保留，无法可靠读取的文件应跳过。第一次可先挑一两段对话，看预览和入库结果再扩大范围。导出文件会交给你的 Agent 读取和处理，提交前先移除你不想交给 Agent 或 CoMem 的内容。

确认后，Agent 用 CoMem MCP 的 `remember` 把消息提交到当前 MCP 身份的个人空间。CoMem 网页所选的空间不会改变这个目标。若 Agent 有 `health` 工具，它会在预览中报告实际账号及是否配置了提炼模型。预览确认只约束 `remember`；若导入聊天开着自动采集，聊天本身仍会正常归档。需要在确认前完全不归档这次聊天时，请在只接入 MCP、未开自动采集的 Agent 或配置中导入。

1. **确认归档。** `remember` 返回实际归档的消息数、归档地址和任务号。到「会话与任务」切回个人空间查看会话。要读原始消息，在「文件树」按地址打开归档下的 `messages.jsonl`，切到「原文」；管理员可以在「任务」页签查后台处理状态。
2. **查看提炼结果。** CoMem 使用和自动采集相同的提炼、合并流程。生效的记忆可以检索；需要确认的条目在「记忆复核」，通过后进入检索。服务端没有配置可用的提炼模型时，归档仍然成功，已跳过提炼的任务不会在补配模型后自动重跑。
3. **补充或整理记忆。** 已经知道要保存哪条事实，可以在「文件树 → 新建记忆」手工录入。配置了可用 LLM 的部署可在设置中开启 Dreamer 手动整理，再从「记忆复核 → 整理建议」检查现有记忆的重复和冲突；这个入口不要求 `summary.generator: llm`。整段旧对话只需要导入，日常提炼和合并不依赖手动整理。

同一路径重跑时，只有会话 ID、角色、正文和提交时间一致的消息才会跳过。Agent 重新识别出的消息边界、正文或时间可能变化，修改后的文本也可能产生新会话。缺失时间用固定占位值，可能显示为 1970 年，并非真实对话日期。自动采集、`pnpm ingest` 和提示词没有跨入口去重，同一份日志宜选一个入口。对于服务进程能直接读取且已支持的宿主格式，大批量导入也可以使用 [`pnpm ingest`](./architecture.md#119-本机-agent-对话导入)。
