# CoMem Rules

规则是**约束**，不是偏好。它们存在 `memories/rules/{scenario}/{rule}.md`，在 CoMem 里是 `memoryType: rules` 的一类记忆。

## 什么时候查

**动手之前**，满足任一条：要改文件或跑命令；任务有评审 / 合规 / 审批环节；用户提到「我们团队」「规定」「必须」；上一次同类任务踩过规则的坑。

**不要查**：只是回答问题、查资料、写一段你自己能判断的代码；`<comem-recall>` 里已经出现 `[rules]` 条目（那是本轮的召回结果，先 `read` 它）。

## 怎么调

`rule_search { "taskContext": "…" }`

- `taskContext` 写**要做什么、涉及哪些对象、有哪些已知约束**，不是关键词。规则靠语义相关度匹配：「nginx」和「上线前要拿到 license 审核」匹配不到一起。
- 把**已知的不确定**也写进去。为了拿到想看的规则而省略事实，等于给自己伪造授权。

返回值是规则的**完整正文**，不是摘要，可以直接据此执行。没有规则时返回 `Found 0 applicable rule(s):`——这是「没有规则」，不是错误，也不是「不用遵守」。

## 怎么用

1. 逐条独立判断：适用条件被当前任务满足吗？有没有例外？
2. 满足就**调整计划**，而不是记下来待会儿提一句。
3. 规则之间冲突时报告冲突，不要自己挑一条执行。
4. 规则是**约束**，不是「未观察到的事实为真」的证据。
5. 上下文被压缩、早期查到的规则可能丢了时，重新查一遍。

`threshold` 默认 `0.65`，语义是**相对本次最高分**的比例：只保留与最佳规则差距不到 35% 的。规则很少时不要调低它去「凑几条」——低分的不是规则。
